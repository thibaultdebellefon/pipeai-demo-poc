# Design: PipeAI Auth + History — Google Login, User Accounts, Diagnosis History

Generated by /brainstorming on 2026-04-01
Status: APPROVED

---

## Problem Statement

PipeAI currently has no user identity. Every session is anonymous and stateless — results disappear when the user closes the tab. Adding Google login, a profile, and diagnosis history turns PipeAI into a persistent tool that plumbers and their managers can return to, review past jobs, and track patterns over time.

---

## Approach

Supabase handles auth (Google OAuth), database (PostgreSQL), and file storage. The Supabase JS client runs in the browser — no new Vercel functions needed. The existing `api/diagnose.js` proxy stays unchanged. Three new HTML pages are added; `app.html` gains a session check and a silent post-diagnosis save.

---

## Architecture

```
New files:
├── config.js          ← shared Supabase client config (public keys)
├── login.html         ← Google sign-in page
├── account.html       ← profile + New Video + My Diagnoses + Logout
├── history.html       ← list of past diagnoses with thumbnails
└── (app.html)         ← modified: session check on load, silent save after diagnosis
```

**Request flow (recording session):**
1. User opens `login.html` → clicks "Continue with Google" → Supabase OAuth → redirected to `account.html`
2. Account page → "New video →" → `app.html`
3. `app.html` checks Supabase session on load — no session → redirect to `login.html`
4. User records, speaks, receives diagnosis
5. After result renders: `app.html` silently uploads 1 JPEG frame to `frames/{user_id}/{uuid}.jpg` and inserts a `diagnoses` row — no visible change to the flow
6. Account page → "My diagnoses" → `history.html`

**Landing page change:**
- `index.html` CTA "Try it now →" now links to `login.html` instead of `app.html`
- `login.html` checks if already logged in — if yes, redirect immediately to `account.html`

**Security:**
- `SUPABASE_URL` and `SUPABASE_ANON_KEY` are public by design — they live in `config.js`, not in Vercel env vars
- Row Level Security (RLS) on all tables and storage buckets: users can only read/write their own data
- Anthropic API key stays in Vercel env vars, untouched

## Supabase Setup

### Database tables

**`profiles`** (extends `auth.users`)
```sql
create table profiles (
  id uuid references auth.users on delete cascade primary key,
  display_name text,
  avatar_url text,
  updated_at timestamptz default now()
);
```

**`diagnoses`**
```sql
create table diagnoses (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references auth.users on delete cascade not null,
  created_at timestamptz default now(),
  frame_url text,
  diagnosis text,
  likely_cause text,
  action_plan jsonb,
  safety_warnings jsonb,
  confidence text check (confidence in ('high','medium','low')),
  notes text
);
```

### Row Level Security policies

```sql
-- profiles: users manage only their own row
alter table profiles enable row level security;
create policy "own profile" on profiles
  for all using (auth.uid() = id);

-- diagnoses: users manage only their own rows
alter table diagnoses enable row level security;
create policy "own diagnoses" on diagnoses
  for all using (auth.uid() = user_id);
```

### Storage buckets

**`frames`** — diagnosis thumbnails (public read, user-scoped write)
**`avatars`** — profile photos (public read, user-scoped write)

```sql
-- frames bucket RLS
create policy "upload own frames" on storage.objects
  for insert with check (bucket_id = 'frames' and auth.uid()::text = (storage.foldername(name))[1]);
create policy "read all frames" on storage.objects
  for select using (bucket_id = 'frames');

-- avatars bucket RLS
create policy "upload own avatar" on storage.objects
  for insert with check (bucket_id = 'avatars' and auth.uid()::text = (storage.foldername(name))[1]);
create policy "update own avatar" on storage.objects
  for update using (bucket_id = 'avatars' and auth.uid()::text = (storage.foldername(name))[1]);
create policy "read all avatars" on storage.objects
  for select using (bucket_id = 'avatars');
```

### Auth config

In Supabase dashboard → Authentication → Providers → Google:
- Enable Google provider
- Add Client ID and Client Secret from Google Cloud Console
- Set redirect URL to: `https://YOUR_VERCEL_URL/account.html`

## `config.js`

Shared by all pages. Loaded via `<script src="config.js">` before any other script.

```javascript
const SUPABASE_URL  = 'https://YOUR_PROJECT.supabase.co';
const SUPABASE_ANON = 'YOUR_ANON_KEY';
```

Supabase JS client loaded from CDN on each page:
```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2/dist/umd/supabase.min.js"></script>
<script src="config.js"></script>
```

Client initialised on each page:
```javascript
const supabase = window.supabase.createClient(SUPABASE_URL, SUPABASE_ANON);
```

## Pages

### `login.html`

Centered card on deep navy background. Brand consistent with `app.html`.

**Layout:**
- PipeAI logo (h1) + tagline
- Single button: "Continue with Google →" (white background, Google "G" logo SVG, black text)
- Small muted text: "Your diagnoses are saved to your account."

**JS behaviour:**
1. On load: check session — if valid, redirect to `account.html`
2. Button click: `supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: window.location.origin + '/account.html' } })`

**Error state:** if OAuth fails, show inline message: "Sign-in failed. Please try again."

---

### `account.html`

**Layout (top to bottom):**

1. **Profile section** (top)
   - Circular avatar (80px) — tap to upload a new photo; placeholder shows initials if no photo set
   - Display name below avatar — tap to edit inline (input appears, saves on blur/Enter)

2. **Primary action** (center, prominent)
   - Large copper orange button: "New video →" → links to `app.html`

3. **Secondary actions** (below primary, side by side)
   - "My diagnoses" button (secondary style) → links to `history.html`
   - "Log out" button (secondary style) → calls `supabase.auth.signOut()`, redirects to `login.html`

**JS behaviour:**
1. On load: check session — no session → redirect to `login.html`
2. Load profile from `profiles` table; if no row exists (first login), insert one with `display_name = null`
3. Avatar upload: `supabase.storage.from('avatars').upload(...)`, then update `profiles.avatar_url`
4. Name edit: update `profiles.display_name` on save

---

### `history.html`

**Layout:**
- Page title: "My diagnoses"
- List, newest first. Each row:
  - Left: thumbnail (56×56px, rounded, object-fit: cover)
  - Right: one-line diagnosis summary (truncated) + relative date ("2 days ago")
  - Tap row → expands inline to show full result card (diagnosis, likely cause, action plan, safety warnings, confidence badge, notes)
- Empty state: "No diagnoses yet. Tap New video to get started."
- Fixed bottom bar: "New video →" button (copper orange)

**JS behaviour:**
1. On load: check session — no session → redirect to `login.html`
2. Fetch all diagnoses for current user: `supabase.from('diagnoses').select('*').order('created_at', { ascending: false })`
3. Render rows; tap toggles expanded state with `classList.toggle('expanded')`

### `app.html` changes

**On load (add to top of script):**
```javascript
const { data: { session } } = await supabase.auth.getSession();
if (!session) { window.location.href = 'login.html'; }
```

**After `renderResult(r)` is called (add one line):**
```javascript
renderResult(r);
saveDiagnosis(r, extractedFrames[0]); // silent, non-blocking
speakResult(r);
```

**New `saveDiagnosis` function:**
```javascript
async function saveDiagnosis(r, firstFrame) {
  try {
    const { data: { session } } = await supabase.auth.getSession();
    if (!session) return;
    const userId = session.user.id;
    const diagId = crypto.randomUUID();

    // Upload first frame to storage
    const blob = await fetch('data:image/jpeg;base64,' + firstFrame).then(r => r.blob());
    const { data: upload } = await supabase.storage
      .from('frames')
      .upload(userId + '/' + diagId + '.jpg', blob, { contentType: 'image/jpeg' });

    const { data: { publicUrl } } = supabase.storage
      .from('frames')
      .getPublicUrl(userId + '/' + diagId + '.jpg');

    // Insert diagnosis row
    await supabase.from('diagnoses').insert({
      id: diagId,
      user_id: userId,
      frame_url: publicUrl,
      diagnosis:        r.diagnosis,
      likely_cause:     r.likely_cause,
      action_plan:      r.action_plan,
      safety_warnings:  r.safety_warnings,
      confidence:       r.confidence,
      notes:            r.notes
    });
  } catch (err) {
    console.warn('Failed to save diagnosis:', err);
    // Silent failure — does not affect the user-facing result
  }
}
```

## Out of scope

- Email/password login
- Account deletion
- Sharing diagnoses with other users
- Push notifications
- Pagination of history (load all for now — suitable for POC)
- Admin dashboard
