# Design: PipeAI v2 — Proxy + Landing Page + Rebrand

Generated by /brainstorming on 2026-03-31
Status: APPROVED

---

## Problem Statement

The Phase 1 PoC (`index.html`) validated that Claude can diagnose plumbing problems from field footage. Phase 2 makes it distributable: hide the API key so any user can access the tool without their own Anthropic account, add a landing page that makes it feel like a real business, fix the UX friction before camera launch, and apply a coherent brand.

---

## Approach

**Two static HTML files + Vercel serverless proxy.** No framework, no build step, no migration risk. The existing diagnostic logic is preserved; the file is renamed and rebrand applied. A new landing page is added. A single Vercel function holds the API key server-side.

---

## Architecture

```
GitHub repo (pipeai-demo-poc)
├── index.html          ← landing page (new)
├── app.html            ← diagnostic tool (renamed + rebrand + UX fixes)
└── api/
    └── diagnose.js     ← Vercel serverless function (API proxy)
```

**Request flow:**
1. User opens `app.html`, records video, speaks description
2. Browser sends frames + transcript as JSON to `/api/diagnose` (POST)
3. `diagnose.js` reads `ANTHROPIC_API_KEY` from Vercel environment variables, calls Anthropic Messages API, returns JSON response
4. `app.html` renders result and reads it aloud via SpeechSynthesis

**Security properties:**
- API key stored only in Vercel environment variables — never in source code, never on GitHub, never visible in browser
- `diagnose.js` is the only file that touches the Anthropic API
- CORS restricted to the Vercel deployment origin
- No user data stored anywhere — stateless proxy, no logging of frames or transcripts

## Sub-project A: Backend Proxy

### File: `api/diagnose.js`

Vercel serverless function (Node.js runtime).

**Request:** POST `/api/diagnose`
```json
{
  "frames": ["base64string", "base64string"],
  "transcript": "string"
}
```

**Behaviour:**
1. Validate request: must have at least 1 frame, frames must be non-empty strings
2. Build Anthropic Messages API payload (same system prompt as current `app.html`)
3. Forward to `https://api.anthropic.com/v1/messages` with `ANTHROPIC_API_KEY` from env
4. Return the raw Anthropic response JSON to the client
5. On Anthropic error (4xx/5xx): return same status code and a plain error message

**CORS:** Allow only the production Vercel domain. During development, also allow `localhost`.

**Environment variable:** `ANTHROPIC_API_KEY` — set in Vercel dashboard, never committed.

**System prompt:** Identical to current `app.html`:
> "You are an expert plumbing diagnostic assistant. Analyse the provided video frames and spoken description to identify the issue, likely cause, and repair path. Always respond with valid JSON only, no markdown fences, matching this schema exactly: {diagnosis, likely_cause, action_plan[{step, action, tools_required}], safety_warnings, confidence: high|medium|low, notes}. Cap action_plan at 5 steps. If the footage is too dark or unclear to diagnose reliably, set confidence to 'low' and explain in notes."

### Landing Page (`index.html`)

Single scrolling page, mobile-first. No navigation bar.

**Section 1 — Hero**
- Full-viewport dark section, vertically centred
- Headline (large, bold): "Your AI plumbing expert, on every job site."
- Subline: "Junior plumbers film the problem, describe it out loud — PipeAI diagnoses it in under 60 seconds."
- CTA button (copper orange): "Try it now →" → links to `app.html`

**Section 2 — How it works**
- Three steps displayed as icon + label + one-line description:
  1. Film — "Point your camera at the problem"
  2. Describe — "Say out loud what you're seeing"
  3. Get your answer — "AI returns a ranked action plan in seconds"
- Stacked on mobile, row on desktop (≥640px)

**Section 3 — Built for the field**
- Three feature cards:
  - "Works in low light" — designed for real job sites, not ideal conditions
  - "One-handed, gloves on" — large touch targets, no tiny UI elements
  - "Under 60 seconds" — from recording end to first recommendation

**Section 4 — Video placeholder**
- Styled dark card, centred play icon, text: "Demo coming soon"
- Swappable with a real `<video>` or YouTube embed later — just replace the card content

**Section 5 — Footer CTA**
- Short copy: "Ready to give your team an expert in their pocket?"
- CTA button (copper orange): "Try it now →" → links to `app.html`
- Footer line: "PipeAI © 2026"

### Tool Page (`app.html`)

Renamed from `index.html`. All diagnostic logic preserved. Two changes: API key removed, prep state added. Brand applied throughout.

**State machine (6 states):**
1. **ready** (new) — instructions + "Start recording →" button. No API key field.
2. **recording** — timer + stop button (unchanged)
3. **processing** — spinner + "Analysing... ~30 seconds" (unchanged)
4. **result** — diagnosis cards + oral response (unchanged)
5. **error** — error message + retry (unchanged)

`ready` replaces `idle` as the entry state. The API key input is removed entirely.

**API call change:**
- Instead of calling `https://api.anthropic.com/v1/messages` directly, `app.html` POSTs `{frames, transcript}` to `/api/diagnose`
- Removes `x-api-key`, `anthropic-version`, and `anthropic-dangerous-direct-browser-access` headers
- All other logic (frame extraction, speech recognition, TTS, result rendering) unchanged

**Error states updated:**
- 401 error message updated: "API configuration error. Contact support." (user can't fix a key they didn't enter)
- 529: "AI service is overloaded. Wait a few seconds and try again." (unchanged)
- Network failure: "Analysis failed. Check your connection and try again." (unchanged)

## Deployment

1. Connect `pipeai-demo-poc` GitHub repo to Vercel (import project)
2. Set `ANTHROPIC_API_KEY` in Vercel → Settings → Environment Variables
3. Vercel auto-deploys on every push to `feature/phase1-poc` (or `main` after merge)
4. GitHub Pages deployment becomes optional — Vercel is the canonical URL

---

## Out of scope

- Authentication / login
- Usage limits or rate limiting per user
- Analytics or session logging
- WhatsApp distribution (deferred per original design)
- React migration (Phase 3)
